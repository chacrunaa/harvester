CLI harv

Вторая версия обходится без сервера и без собственного интерфейса. Состояние задачи лежит в каталоге .notes/ внутри проекта, роли исполняют агенты в обычных чатах редактора, а CLI отвечает за дисциплину: кто имеет право взять задачу, что обязано появиться перед передачей дальше и что делать при конфликте.

Python 3.11 и только стандартная библиотека — ни одной сторонней зависимости. 24 команды, 65 тестов.

Записанный прогон

Ниже — настоящий прогон, записанный скриптом tools/trace-cli.py во временном каталоге с подменённым HOME. Ключи LLM не нужны: harv не ходит в сеть, это машина состояний над файлами. Два шага помечены крестиком — это не поломка, а сработавшие проверки, ради которых всё и затевалось.

Задача HARV-004 — «Добавить экспорт отчётов в CSV»
Источник: ui/data/cli-run.js
13 шагов

Два интересных места

ШагЧто проверяет
advance … --to architecture Стадия analysis обязана оставить три артефакта. Их нет — передача отклонена с перечислением недостающих файлов. Мало создать файл: его нужно ещё зарегистрировать через add-artifact, иначе гейт сообщит artifact_not_registered.
advance … --expect-revision 999 Оптимистичная блокировка. Агент заявляет, какую ревизию он видел; если за это время задачу изменил другой чат, команда отказывает с stale_revision вместо того, чтобы затереть чужую работу.

Модель работы

Восемь стадий, собранных в четыре группы — по группе на чат. Правило одного писателя: чат берёт только те задачи, у которых current_stage совпадает с его стадией. Поэтому четыре чата можно держать открытыми одновременно — они физически не могут взять одну задачу.

ГруппаСтадииСлово активации
planintake → analysis → architectureharv-planning
devbackend, frontend, integrationharv-dev
testingtestharv-testing
reviewreviewharv-review

Ключевое слово перехватывает хук UserPromptSubmit (ai/adapters/claude-hook) и подкладывает в контекст инструкции роли — агенту не нужно объяснять правила вручную.

Протокол записи

перед записью   перечитать task.json
                сверить runtime.revision, current_stage и lease (TTL 120 мин)
после записи    увеличить revision
                добавить событие в events
                перенести task_id между queue.json стадий

Контракт лежит рядом с данными: .notes/tasks/backlog/stages.json.

Команды

24 команды, у каждой есть --json для машиночитаемого вывода.

Запуск

cd cli/backend
make install                                # обёртка dist/harv
ln -sf "$PWD/dist/harv" ~/.local/bin/harv

harv init /path/to/project --personal
harv create "Описание задачи"
harv status HARV-004

make test                                   # 65 тестов

Без установки CLI запускается напрямую: app/src/main --help. На свежей копии make projects честно скажет, что проектов нет, — пока не выполнен harv init.

Ограничения

fanout не доводит ветки до конца без провайдера. Группу ветвей и барьер он создаёт, но исполнять ветки должен sub-agent — для этого нужен настроенный провайдер модели. В записи выше барьер честно отказывает.

make chat не открывает чат. Он печатает готовый промпт и команду для вставки.

templates/ — пока заготовка под будущие template init и template update.

Тестов фронтенда нет, потому что нет и фронтенда: вся работа идёт из терминала и чатов.
