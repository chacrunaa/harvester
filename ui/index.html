Harvester

Конвейер, который проводит продуктовую задачу через фазы — бизнес-анализ, системное проектирование, разработку и тестирование. Каждую фазу ведёт агент-оркестратор, часть работы идёт параллельно, между фазами стоят гейты. Две версии продукта: движок-сервер и переосмысление того же в виде CLI.

Движок конвейера v1

Go-сервис: watcher состояния на fsnotify, порядок фаз, AND-гейты, REST и WebSocket. Веб-интерфейс на React и TypeScript.

Go 1.22 Gin WebSocket fsnotify React 18 TypeScript Vite Docker CLI harv v2

Та же идея без сервера: состояние задачи лежит в файлах проекта, роли исполняют агенты в чатах, а CLI держит очереди, ревизии и гейты.

Python 3.11 без зависимостей 24 команды 65 тестов

Почему версий две

Первая версия — полноценный сервис: он сам вызывает модель, следит за файлами и показывает прогресс в браузере. Это работает, но требует поднятого сервера, ключей и собственного интерфейса под каждый шаг.

Вторая версия убирает сервер. Агенты и так живут в редакторе с чатом, а значит нужен не ещё один интерфейс, а дисциплина: кто имеет право трогать задачу, какие артефакты обязаны появиться перед передачей дальше, что делать при конфликте. Поэтому v2 — это CLI и машина состояний в файлах, которую одинаково видят человек и агент.

Запуск

cd engine && make install && make dev   # API :3100, интерфейс :5173
cd cli/backend && make test            # 65 тестов, ключи не нужны

Витрина — статические файлы: открывается двойным кликом по ui/index.html, сборка и сервер не нужны.

Пет-проект. Данные в проигрывателях записаны автоматическими прогонами настоящего кода, а не нарисованы вручную.
