# Инфраструктура Harvester

Главная точка входа для всего, что связано с деплоем и эксплуатацией.
Читай этот файл первым — он объясняет общую картину и куда идти дальше.

## Что здесь находится

```
infra/
├── terraform/      # Создание серверов в облаке (Yandex или Hetzner)
├── cloud-init/     # Автоматическая настройка сервера при первом запуске
├── docker/         # Dockerfile и docker-compose для всех окружений
└── server/         # Конфиги, которые живут на сервере (Caddy, мониторинг)
```

## Стек

| Компонент | Технология |
|---|---|
| **API сервер** | Go + Gin + WebSocket |
| **Pipeline watcher** | Go + fsnotify — библиотека внутри процесса API, не отдельный сервис |
| **Reverse proxy / SSL** | Caddy (автоматический Let's Encrypt) |
| **CDN / DNS** | Cloudflare |
| **Облако (prod)** | Hetzner Cloud |
| **Облако (staging)** | Yandex Cloud |
| **CI/CD** | нет — образы собираются и публикуются вручную |

## Общий порядок действий

```
Шаг 1 → Шаг 2 → Шаг 3 → Шаг 4
Terraform   cloud-init   docker-    Мониторинг
(создать    (сервер      compose
 сервер)     настроит    (запустить
             сам себя)   приложение)
```

### Шаг 1 — Создать сервер через Terraform

| Окружение | Провайдер | Когда использовать |
|---|---|---|
| **Тест / Staging** | Yandex Cloud | Уже оплачено, быстро поднять |
| **Production** | Hetzner Cloud | Европа, дешевле |

→ Подробнее: [terraform/README.md](terraform/README.md)

### Шаг 2 — Сервер настроится автоматически

Terraform передаёт cloud-init скрипт. Скрипт автоматически устанавливает Docker,
Caddy, GitLab Runner и создаёт нужные директории.
Ничего делать вручную не нужно — сервер сам себя настраивает за ~3 минуты.

→ Подробнее: [cloud-init/README.md](cloud-init/README.md)

### Шаг 3 — Запустить приложение

После того как сервер готов:
1. Скопировать `.env` файл на сервер
2. Запустить `docker compose up -d`

Контейнер один — `api` (Go). Watcher конвейера работает внутри этого же
процесса как Go-библиотека (`.ai/scripts`), отдельным сервисом он не бывает.
Образ собирается вручную: CI в этом репозитории нет.

→ Подробнее: [docker/README.md](docker/README.md)

### Шаг 4 — Настроить мониторинг

- **Мониторинг**: Uptime Robot следит за `/health` и шлёт алерты в Telegram
- **Диск**: скрипт `disk-monitor.sh` по cron каждые 30 минут проверяет заполненность

→ Подробнее: [server/README.md](server/README.md)

## Что где хранится на сервере

```
/opt/harvester/
├── docker-compose.yml   # production compose (из infra/docker/docker-compose.prod.yml)
└── .env                 # секреты (LLM API ключи, APP_ENV)

/opt/backup/
└── .env                 # Telegram credentials для disk-monitor.sh

/etc/caddy/Caddyfile     # конфиг reverse proxy
```

## Состояние

Инфраструктура описана целиком (Terraform для двух облаков, cloud-init,
Caddy, мониторинг диска), но **на реальный сервер не разворачивалась** —
проект запускался только локально. Образ собирается и healthcheck проходит,
всё остальное из этого каталога стоит считать проектом, а не проверенным
в бою рантаймом.
