# Инструкция 11 — Определение MVP

## Роль AI-агента

> Ты продакт-менеджер с Lean Startup подходом и опытом запуска MVP. Твоя задача — определить минимальный жизнеспособный продукт, сформулировать гипотезы, настроить цикл их проверки через HADI и спланировать запуск.

## Теоретическая база (из курса «Создание продуктовой концепции», модуль 2)

### Продуктовый подход к MVP

**MVP** — это не «дешёвая версия продукта». Это инструмент для проверки ключевых гипотез с минимальными затратами ресурсов.

**Lean-подход (бережная разработка):**
- Создавать ценность, сокращая расходы на её производство
- Разрабатывается часть продукта → тестируется на реальных пользователях → принимается решение о дальнейшем направлении

**Главный риск проектного подхода** — получить продукт, полностью соответствующий ТЗ, но не реалиям рынка (изменились потребности, конкуренты обогнали).

**Плюс продуктового подхода** — гораздо реже возникает риск создания ненужного продукта.

### Типы гипотез (по курсу)

| Тип гипотезы | Что проверяем | Пример |
|-------------|--------------|--------|
| **О потребностях** | Проблема существует у пользователей | «Пользователи бросают курсы из-за отсутствия мотивации» |
| **О продукте** | Функция решает проблему | «Геймификация повысит Completion Rate» |
| **О конкурентной среде** | Чем выделиться | «Персонализация — незакрытая ниша конкурентов» |
| **О бизнес-модели** | Как монетизировать | «Пользователи готовы платить 500–1000 руб/мес» |
| **О рынке** | Тренды и доступность | «Рынок EdTech растёт на 20% в год» |

### Формула гипотезы (по курсу)

```
Мы верим, что [предположение].
Чтобы это проверить, мы [конкретные действия].
И измерим [инструмент / метрика].
Мы окажемся правы, если [критерий подтверждения].
```

**4 принципа хорошей гипотезы:**
1. **Двоичный результат** — только «подтверждена» или «опровергнута»
2. **Неочевидность** — не проверяем общеизвестные факты
3. **Возможность проверки** — должен существовать метод проверки
4. **Измеримость** — должны быть инструменты для измерения показателя

### HADI-цикл

Для системной работы с гипотезами используй цикл HADI:

```
H — Hypothesis (гипотеза)     → Формулируем конкретную гипотезу
A — Action (действие)         → Запускаем проверку
D — Data (данные)             → Собираем и обрабатываем данные
I — Insights (инсайты)        → Делаем выводы, принимаем решение
```

**6 принципов работы HADI-цикла:**

1. **Конкретная гипотеза** — какой показатель тестируется? Ускорит ли это развитие?
2. **Измеримый результат** — что конкретно получим? Число регистраций, конверсий, продаж?
3. **Достижимая цель** — есть ли ресурсы для проверки? Если нет — разбей на подзадачи
4. **Ограничение по времени** — 1 HADI-цикл = до 2 недель
5. **Формат «если…, то…»** — гипотеза должна допускать ответ «да» или «нет»
6. **Одна гипотеза на показатель** — нельзя одновременно менять цвет кнопки + текст + способы оплаты

**Результат HADI:** внедрить / доработать и повторить / отклонить.

### Методы приоритизации фич (RICE)

```
RICE Score = (Reach × Impact × Confidence) / Effort
```

Используй при отборе функций для MVP.

## Задача

### 1. Определение MVP

**MVP в одном предложении:**
> «MVP [название продукта] — это [краткое описание], который позволяет [приоритетному сегменту] [выполнить ключевую задачу], достаточный для [проверки главной гипотезы].»

**Главная гипотеза, которую проверяет MVP:**
> Мы верим, что [ключевое предположение]. Мы окажемся правы, если [измеримый критерий].

**Критерии включения в MVP:**
- Решает ключевую проблему приоритетного сегмента
- Позволяет начать получать (пусть и немного) платящих пользователей
- Достаточен для проверки 2–3 ключевых гипотез

### 4. User Journey для MVP

Путь пользователя от первого касания до получения ценности:

```
Осведомлённость → Регистрация → Онбординг → [Ключевое действие 1] 
→ [Ценность / Aha Moment] → Возврат → Конверсия в платёж
```

**Детальное описание каждого шага:**

| Шаг | Что видит пользователь | Что делает | Что чувствует | Что может пойти не так |
|-----|----------------------|-----------|--------------|----------------------|
| 1. Регистрация | … | … | … | Слишком длинная форма → отток |
| 2. Онбординг | … | … | … | … |
| 3. Первое действие | … | … | … | … |
| 4. Aha Moment | … | … | … | … |
| 5. Повторное использование | … | … | … | … |
| 6. Оплата | … | … | … | … |

**Aha Moment (первый момент ценности):**  
Конкретное действие или экран, после которого пользователь понимает ценность продукта:  
> «Когда пользователь [конкретное действие], он понимает, что [ценность].»  
Цель: достичь Aha Moment за … дней/сессий.

### 6. Plan работы HADI-циклов (первые 8 недель)

```
Неделя 1–2:  [Гипотеза #1] → запуск → сбор данных → инсайт
Неделя 3–4:  [Гипотеза #2] → запуск → сбор данных → инсайт
Неделя 5–6:  [Гипотеза #3] → запуск → сбор данных → инсайт
Неделя 7–8:  Анализ всех результатов → решение о пивоте / продолжении
```

**Дерево решений по итогам HADI:**

| Результат | Решение |
|----------|---------|
| ≥70% гипотез подтверждены | Продолжать текущую концепцию, выходить на v1.0 |
| 50–70% гипотез подтверждены | Доработать, провести ещё 1–2 цикла |
| <50% гипотез подтверждены | Пивот концепции или сегмента |
| Проблема не существует для большинства | Остановить разработку |

### 8. Метрики валидации MVP

Что считается успехом MVP (конкретные пороговые значения):

| Метрика | Порог «MVP провалился» | Порог «Нужна доработка» | Порог «MVP успешен» |
|---------|----------------------|------------------------|---------------------|
| Activation Rate (D7) | < 20% | 20–39% | ≥ 40% |
| Retention D30 | < 15% | 15–29% | ≥ 30% |
| Конверсия free→paid | < 3% | 3–6% | ≥ 7% |
| NPS | < 30 | 30–59 | ≥ 60 |
| Aha Moment (% пользователей) | < 25% | 25–49% | ≥ 50% |

**Инструменты замера:**
- Activation / Retention: Amplitude, Mixpanel
- NPS: опрос in-app (Hotjar)
- Конверсия: CRM, ЮKassa

## Фреймворки

- **HADI-цикл** (Hypothesis → Action → Data → Insights) — из курса «Создание продуктовой концепции», модуль 2
- **MoSCoW** — приоритизация требований
- **RICE** (Reach × Impact × Confidence / Effort) — приоритизация фич
- **Lean Startup** (Build-Measure-Learn) — Эрик Рис
- **Lean Prioritization** (Quick Wins / Big Bets / Maybes / Time Sinks)

## Критерии качества

- [ ] MVP определён одним чётким предложением с главной гипотезой
- [ ] Включены только Must требования из БФТ с обоснованием через RICE
- [ ] User Journey описан по всем шагам с Aha Moment
- [ ] Гипотезы сформулированы по шаблону курса с измеримыми критериями
- [ ] HADI-план расписан по неделям на 8 недель
- [ ] Дерево решений по итогам HADI присутствует
- [ ] Метрики валидации имеют 3 пороговых уровня
- [ ] Roadmap содержит 3 версии с метриками
- [ ] Go-to-Market план конкретен: откуда первые 100 пользователей
