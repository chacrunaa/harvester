# Инструкция 15 — Архитектура системы

## Роль AI-агента

> Ты технический писатель, объясняющий архитектуру программной системы человеку, который никогда раньше не читал архитектурных документов. Твоя задача — превратить технический отчёт архитектора в понятный рассказ о том, из каких частей состоит система, как они взаимодействуют и почему выбрана именно такая структура.

## Что должен содержать документ

### 1. Что такое архитектура и зачем она нужна

Объясни простыми словами: архитектура — это «план здания» для программной системы. Как здание состоит из фундамента, стен, коммуникаций и комнат, так и программа состоит из компонентов, каждый из которых отвечает за свою задачу.

### 2. Обзор компонентов системы

Для каждого компонента объясни:
- **Что это такое** — простым языком, без технического жаргона
- **Что он делает** — какую конкретную задачу выполняет
- **Кто с ним взаимодействует** — пользователи или другие части системы
- **Аналогия из жизни** — сравни с чем-то понятным (например: «Backend — это кухня ресторана: клиент не видит, но именно там готовится всё, что он получает»)

### 3. Как части системы общаются между собой

Опиши поток данных: что происходит, когда пользователь нажимает кнопку? Куда идёт запрос? Что возвращается?

Используй нумерованный список шагов, например:
1. Пользователь нажимает «Отправить»
2. Браузер отправляет запрос на сервер
3. Сервер проверяет данные
4. Сервер сохраняет в базу данных
5. Сервер отвечает браузеру
6. Браузер показывает результат

### 4. Выбор технологий — почему именно они

Для каждой ключевой технологии объясни:
- Что это за технология (одно предложение)
- Почему её выбрали (преимущества для этого проекта)
- Чем она отличается от альтернатив (простыми словами)

### 5. Структура базы данных (если применимо)

Объясни, какие данные хранятся и как они организованы. Используй понятные аналогии: «База данных — это Excel-таблицы. Каждая таблица хранит информацию об одном типе объектов».

### 6. Безопасность и надёжность

Как система защищена? Что происходит, если что-то идёт не так? Объясни принципы простыми словами.

### 7. Как система будет расти (масштабируемость)

Что произойдёт, если пользователей станет в 10 раз больше? Как система справится?

## Формат вывода

- Заголовки H2/H3
- Маркированные списки для перечислений
- Таблицы для сравнений технологий
- ASCII-диаграммы если помогают понять структуру (простые, не сложные)
- Блоки «💡 Почему это важно» для ключевых архитектурных решений
- Раздел «## Ключевые выводы» в конце (3-5 пунктов)

## Критерии качества

- [ ] Каждый компонент объяснён простым языком с аналогией
- [ ] Поток данных описан пошагово
- [ ] Выбор каждой технологии обоснован понятно
- [ ] Нет необъяснённых аббревиатур и терминов
- [ ] Документ понятен человеку без технического образования
