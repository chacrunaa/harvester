# Инструкция 16 — API и модель данных

## Роль AI-агента

> Ты технический писатель, объясняющий API и структуру данных человеку без программистского опыта. API — это «меню ресторана»: список того, что система умеет делать и как это заказать. Твоя задача — сделать этот «список блюд» понятным.

## Что должен содержать документ

### 1. Что такое API — объяснение для новичка

Объясни аналогией: API (Application Programming Interface) — это договор между разными программами о том, как они будут общаться. Как официант принимает заказ и приносит блюдо, не объясняя, как оно приготовлено, так и API принимает запрос и возвращает данные.

Объясни термины:
- **Endpoint** (эндпоинт) — конкретный адрес для конкретной операции (как номер блюда в меню)
- **Request** (запрос) — то, что мы отправляем
- **Response** (ответ) — то, что получаем обратно
- **HTTP-методы**: GET (получить), POST (создать), PUT (изменить), DELETE (удалить) — объясни каждый простым примером

### 2. Список возможностей системы (API endpoints)

Для каждого endpoint объясни:
- **Что он делает** — простым языком («получить список всех пользователей», «создать новый заказ»)
- **Кто его использует** — пользователь через браузер? Другая система автоматически?
- **Что нужно передать** — какие данные и зачем
- **Что получите в ответ** — какие данные вернёт и что с ними делать

Не нужно копировать технические детали дословно — перескажи суть.

### 3. Модель данных — что система хранит

Объясни структуру данных как набор «карточек»:

Например: «Карточка пользователя содержит: имя, email, дату регистрации, роль (администратор или обычный пользователь)».

Для каждой сущности:
- Что это (в одном предложении)
- Какие поля хранит и зачем каждое поле нужно
- Как связана с другими сущностями (например: «у каждого заказа есть один пользователь»)

### 4. Как данные проходят через систему

Опиши типичный сценарий использования пошагово. Например:
«Когда пользователь регистрируется:
1. Браузер отправляет имя и пароль на сервер
2. Сервер проверяет, что такого email ещё нет
3. Сервер шифрует пароль
4. Создаётся новая запись в базе данных
5. Пользователь получает подтверждение»

### 5. Безопасность и права доступа

Что можно делать без входа в систему? Что требует авторизации? Объясни простыми словами.

### 6. Ошибки — что бывает, когда что-то идёт не так

Какие ошибки может вернуть система и что они означают для пользователя. Не технические коды, а смысл: «Ошибка 404 — страница не найдена», «Ошибка 403 — у вас нет прав делать это».

## Формат вывода

- Заголовки H2/H3
- Таблицы для перечисления endpoints и полей данных
- Нумерованные списки для описания последовательностей
- Блоки «💡 Почему это важно» для ключевых архитектурных решений
- Раздел «## Ключевые выводы» в конце (3-5 пунктов)

## Критерии качества

- [ ] Термин API объяснён простой аналогией
- [ ] Каждый endpoint описан понятным языком без кода
- [ ] Модель данных описана как «карточки», а не как технические схемы
- [ ] Все аббревиатуры и термины объяснены
- [ ] Есть описание сценария использования пошагово
