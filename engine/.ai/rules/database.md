# Правила repository и SQL

## Repository

- Repository выполняет фильтрацию, scope-ограничения и пагинацию на уровне SQL, а не через водопад последовательных запросов в service.
- Предпочтительны 1-2 понятных запроса вместо одного чрезмерно сложного монолита.
- N+1 по командам, ролям и связанным данным устраняются батч-запросами или предсказуемой агрегацией.
- SQL остаётся в repository слое. Прямые cross-schema SQL запрещены.
- DTO HTTP transport лежат в `internal/infrastructure/integration/inbound/http/dto/**`.
- Mapper-логика лежит в `internal/conversion/mapper/**` и не содержит бизнес-логики.

## Индексы и поиск

- Поиск и индексы добавляются только под подтверждённые сценарии.
- Нельзя вводить полнотекстовый поиск, триграммы и дополнительные поля, если бизнес-задача требует только выборку по `id`/`email`.
- Любая оптимизация SQL должна учитывать реальные поля поиска и реальные фильтры из задачи, а не гипотетические будущие сценарии.
