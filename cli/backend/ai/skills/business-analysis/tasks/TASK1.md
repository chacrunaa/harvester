# TASK1 — Анализ входных материалов и формирование вопросов

## Цель

Прочитать все доступные материалы по проекту, оценить достаточность информации и — если данных не хватает — сформировать уточняющие вопросы. Одновременно с вопросами создать задание для их обработки.

---

## Алгоритм

```
Шаг 1: Прочитать data/input/ и data/info/
           ↓
Шаг 2: Оценить — хватает ли данных для TASK3?
           ↓ НЕТ                     ↓ ДА
Шаг 3: Создать вопросы         Ничего не делать →
        в questions/            переходить к TASK2
           ↓
Шаг 4: Создать задание
        tasks/TASK1q/q1.md
        (описывает что делать с ответами)
           ↓
        Ждать ответов клиента
           ↓
        Клиент ответил → выполнить tasks/TASK1q/q1.md
           ↓
        Снова Шаг 2 (если пробелы остались → q2.md и т.д.)
```

---

## Шаг 1 — Прочитать все материалы

Читать в таком порядке:
1. Все файлы в `data/input/` (включая вложенные папки)
2. Все файлы в `data/info/` (если уже есть — результаты предыдущих итераций)

Зафиксировать ключевые факты:
- Название продукта, категория, суть проблемы и решения
- ICP-сегменты (кто покупает, кто платит)
- Ценовые якоря, модель монетизации, тарифы
- Конверсии воронки (visit→signup, signup→payment)
- Конкуренты — названия и ключевые характеристики
- Технический стек, архитектурные решения
- Команда, ФОТ, OPEX
- Временные рамки: пилот, MVP, горизонт планирования
- Целевые KPI на 6 и 12 месяцев

---

## Шаг 2 — Оценить достаточность данных

Проверить минимальный набор, без которого нельзя продолжать:

| Параметр | Есть? |
|---------|:-----:|
| Целевая география и горизонт планирования | |
| ≥1–3 приоритетных ICP-сегмента для MVP | |
| Хотя бы примерная ценовая сетка (диапазон или конкретные числа) | |
| Целевые KPI на 6 и 12 мес | |
| Понимание структуры расходов (хотя бы укрупнённо) | |
| ≥1–3 названных конкурента | |

**Если все пункты закрыты** — вопросов не задавать, переходить к TASK2.

**Если есть незакрытые пункты** — переходить к шагам 3–4.

---

## Шаг 3 — Сформировать вопросы

Создать файл: `questions/ГГГГ-ММ-ДД-[тема].txt`

Правила:
- Не задавать вопрос, если ответ уже есть в материалах
- Группировать по темам: ЦА, ценообразование, KPI, конкуренты, расходы
- В каждом вопросе — одна строка зачем он нужен (для какого шага TASK3)
- Лучше 5 точных вопросов, чем 20 размытых
- Добавить в файл пример желаемого формата ответа (облегчает клиенту)

Смотри пример файла вопросов: [`questions/readme.md`](../questions/readme.md)

---

## Шаг 4 — Создать задание для обработки ответов

**Одновременно** с созданием файла вопросов создать:  
`tasks/TASK1q/q1.md` (или `q2.md` при следующей итерации)

Этот файл описывает:
- Какой файл вопросов был создан
- Какие темы охвачены
- Что именно создать в `data/info/` после получения ответов
- Критерии готовности

Смотри формат и пример: [`tasks/TASK1q/readme.md`](TASK1q/readme.md)

---

## Правила

- Читать и `data/input/`, и `data/info/` — не только input
- Если данных достаточно — не задавать вопросы ради вопросов
- Вопросы и задание создаются **одновременно**, не по отдельности
- Если пробелы критичны (блокируют финмодель или юнит-экономику) — задавать обязательно
- Если пробелы некритичны — можно отметить как `[гипотеза]` и продолжать

---

## Результат

**Вариант A — данных достаточно:**
- Никаких файлов не создаётся
- Переходим к TASK2

**Вариант B — данных не хватает:**
- `questions/ГГГГ-ММ-ДД-[тема].txt` — файл с вопросами для клиента
- `tasks/TASK1q/q1.md` — задание по обработке ответов
- После получения ответов → выполнить `tasks/TASK1q/q1.md` → снова оценить
