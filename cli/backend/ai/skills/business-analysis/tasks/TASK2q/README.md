# tasks/TASK2q — Задания для обработки ответов на вопросы TASK2

Эта директория содержит задания, которые AI-агент создаёт **одновременно** с формированием дополнительных вопросов в ходе TASK2.

TASK2 — итеративный процесс. Когда при повторном анализе всех материалов (data/input + data/info + questions + instructions + data/output) обнаруживаются критичные пробелы, агент задаёт новые вопросы в `questions/` и сразу создаёт задание здесь — что делать с ответами.

---

## Чем отличается от TASK1q

| | TASK1q | TASK2q |
|--|--------|--------|
| Когда создаётся | В ходе первичного TASK1 | В ходе итераций TASK2 |
| Цель обработки ответов | Создать новый файл в `data/info/` | Дополнить документ `data/output/00-business-context.md` |
| Контекст | Только `data/input/` | Весь контекст: input + info + questions + output |

---

## Когда появляются файлы здесь

Файлы создаются в `tasks/TASK2q/` **только если** в ходе TASK2 были сформированы новые вопросы.

Если вопросов не возникло — директория остаётся пустой, это означает что TASK2 завершён.

---

## Формат файлов

**Имя файла:** `q1.md`, `q2.md`, ... — по номеру раунда вопросов внутри TASK2.

**Структура каждого файла:**

```markdown
# TASK2-Q[N] — Задание по обработке ответов (дата)

## Что нужно сделать

Прочитать ответы клиента из файла: `questions/[имя-файла-с-вопросами]`

Затем дополнить документ: `data/output/00-business-context.md`

(Если документ ещё не существует — создать его по структуре из TASK2.md)

## Какие вопросы были заданы и зачем

[Резюме тем вопросов + почему они критичны для продолжения TASK3]

## Какие разделы 00-business-context.md нужно обновить

- Раздел X — [что именно добавить / уточнить]
- Раздел Y — [что именно добавить]
- Раздел «Открытые вопросы» — [обновить / закрыть пункты]

## Критерии готовности

- [ ] Файл data/output/00-business-context.md обновлён
- [ ] Ответы структурированы (факт / гипотеза — явно разделены)
- [ ] Раздел «Открытые вопросы» обновлён
- [ ] Снова оценено: можно переходить к TASK3 или нужен ещё раунд?
```

---

## Пример реального файла

**Файл:** `tasks/TASK2q/q1.md`

```markdown
# TASK2-Q1 — Задание по обработке ответов (2024-11-20)

## Что нужно сделать

Прочитать ответы клиента из: `questions/2024-11-20-kpi-financials.txt`

Дополнить документ: `data/output/00-business-context.md`

## Какие вопросы были заданы

Блок 1 — KPI и целевые метрики:
- Сколько платящих пользователей планируется на 6 мес? На 12 мес?
- Какой целевой MRR через год?
- Какой NPS считается приемлемым?

Блок 2 — Финансы:
- Какой ФОТ команды сейчас? Будет ли меняться?
- Есть ли бюджет на маркетинг в первые 6 мес?

## Что обновить в 00-business-context.md

- Раздел «Факты о бизнесе» → строки KPI 6 мес, KPI 12 мес, ФОТ
- Раздел «Открытые вопросы» → закрыть пункты H3, H5 если ответы получены

## Критерии готовности

- [ ] Таблица фактов в 00-business-context.md заполнена числами
- [ ] Гипотезы, которые теперь стали фактами — помечены как подтверждённые
- [ ] Пробелы, которые не закрылись — явно перечислены
- [ ] Принято решение: GO к TASK3 или ещё один раунд
```

---

## Связь с другими файлами

```
TASK2.md (итерации)
  → обнаруживает пробелы → создаёт вопросы в questions/[дата]-[тема].txt
  → создаёт задание здесь: tasks/TASK2q/q1.md
       ↓
  Клиент отвечает
       ↓
  tasks/TASK2q/q1.md → инструктирует обновить data/output/00-business-context.md
       ↓
  Если все критичные пробелы закрыты → TASK3.md
  Если нет → новая итерация TASK2, создаётся q2.md
```

## Признак завершения TASK2

Если в `tasks/TASK2q/` нет новых файлов и `data/output/00-business-context.md` создан и заполнен — TASK2 завершён, можно запускать TASK3.
