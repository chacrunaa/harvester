# Доменные инструкции — обзор

Этот раздел содержит дополнительные инструкции анализа для конкретных типов бизнеса. Используется в **TASK4** после прохождения основного анализа (TASK3).

## Когда использовать

После завершения основных 14 шагов (TASK3), определить тип бизнеса по `data/info/` и `data/output/06-business-model/` и запустить соответствующий доменный анализ через **TASK4**.

## Доступные домены

| Домен | Когда применять | Дополнительные документы |
|-------|----------------|--------------------------|
| [marketplace](./marketplace/) | Двусторонняя платформа: продавцы + покупатели, GMV-модель | GMV-экономика, ликвидность, CAC поставщиков |
| [ecommerce](./ecommerce/) | Интернет-магазин: физические или цифровые товары, складская модель | SKU-анализ, инвентарь, логистика, сезонность |
| [b2b-saas](./b2b-saas/) | SaaS для бизнеса: корпоративные продажи, ARR, enterprise | Sales funnel, ARR/NRR, churn, expansion revenue |
| [mobile-app](./mobile-app/) | Мобильное приложение: iOS/Android, DAU-центричная модель | DAU/MAU, ASO, монетизация, push CTR |

## Как определить домен

1. Прочитать `data/info/` — там должен быть тип бизнеса
2. Если не указан явно — определить по бизнес-модели из `data/output/06-business-model/`:
   - Есть две стороны (поставщики + покупатели) → **marketplace**
   - Продаются физические/цифровые товары со складской логикой → **ecommerce**
   - Клиенты — компании, длинный цикл продаж, ARR → **b2b-saas**
   - Основной канал — мобильное приложение, DAU — главная метрика → **mobile-app**
3. Один проект может подходить под несколько доменов — запускать все релевантные

## Структура выходных документов

```
data/output/15-domains/
  marketplace/
  ecommerce/
  b2b-saas/
  mobile-app/
```
